# NFeGov 2.0 — Plano de Implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reconstruir o NFeGov como uma aplicação central multitenant — API REST Laravel 13 + SPA React — que recebe e consulta NF-e da SEFAZ via certificado e-CNPJ por unidade, com segurança de credenciais e proteção contra bloqueio do fisco.

**Architecture:** Monorepo com `backend/` (Laravel 13, API REST pura, Sanctum cookie same-origin) e `frontend/` (React + Vite, buildado para `backend/public`). Multitenancy por banco único com `tenant_id` + global scope. A integração SEFAZ vive numa camada de domínio sobre `nfephp-org/sped-nfe`, isolada do HTTP. Sincronização por jobs no Redis/Horizon, protegida por freio global anti-bloqueio.

**Tech Stack:** PHP 8.4, Laravel 13, `nfephp-org/sped-nfe ^5.2`, `nfephp-org/sped-da ^1.1`, `laravel/sanctum ^4.3`, `laravel/horizon ^5.50`, `spatie/laravel-permission ^8.3`, React + Vite + TypeScript, TanStack Query, **PostgreSQL 16**, Redis 7.

**Spec:** `docs/nfegov/2026-11-03-nfegov-design.md`

## Global Constraints

- **Tudo em Docker.** Nada roda direto no host: PHP-FPM, Nginx, PostgreSQL e Redis sobem por `docker compose`. O host só precisa de Docker.
- **Banco: PostgreSQL 16** (não MySQL/MariaDB). Driver `pgsql`.
- PHP **8.4** (Laravel 13 exige `>= 8.4`). `sped-nfe` é testada oficialmente no 8.4 (matriz de CI 7.4→8.5).
- Laravel **13.x**, Spatie **^8.3**, Sanctum **^4.3**, Horizon **^5.50**.
- `nfephp-org/sped-nfe` **^5.2**, `nfephp-org/sped-da` **^1.1** (ambas `php: >= 7.4`, sem teto).
- Extensões PHP obrigatórias: `zlib, dom, openssl, soap, json, simplexml, libxml, curl, zip, mbstring, pdo_pgsql`.
- **Multitenancy:** `tenant_id` em toda tabela de domínio; global scope obrigatório; nenhum query cruza tenants.
- **Certificado:** PFX cifrado em disco; senha com cast `encrypted`; **nenhum endpoint expõe PFX ou senha**.
- **MFA (TOTP)** obrigatório para `super-admin` e `admin-tenant`; step-up em rotação de certificado.
- **RBAC:** papéis `super-admin`, `admin-tenant`, `operador`, `consulta` (Spatie).
- **Fila:** Redis + Horizon. Fila `sefaz` com concorrência 1–2.
- **Freio SEFAZ por unidade:** 150 iterações no catch-up (`ultNSU==0`), 100 depois; `sleep(2)`; break em `cStat 656`.
- **Freio global:** rate limiter `sefaz-distdfe`; circuit breaker que pausa a fila `sefaz` por 1h em qualquer `656`; escalonamento das unidades na janela de 3h.
- **Manifestação:** apenas ciência da operação (`210210`), automática ao receber `resNFe`.
- **XML imutável**, nunca excluível (nem por `super-admin`); todo download auditado; URL assinada temporária.
- **Idempotência** por chave de acesso; cursor NSU avança por documento em transação.
- Timezone `America/Sao_Paulo`; agendamento a cada 3h em dias úteis.
- Repositório remoto: `https://github.com/helesjunior/nfegov2.0.git` (branch `main`).

## Review Focus

Inputs/condições que o spec implica e que mais provavelmente quebram no uso real — cada um ganha teste na tarefa dona do código:

1. **Certificado vencido ou revogado no momento do sync:** o job deve falhar com erro claro em `sync_runs` e alertar, nunca travar silenciosamente. (Task 12)
2. **`cStat 656` recebido por uma unidade:** toda a fila `sefaz` pausa por 1h para todos os tenants. (Task 15)
3. **Nota que chega só como `resNFe` (resumo):** grava em estado `resumo`, dispara ciência automática e depois baixa o XML completo. (Task 13)
4. **Tentativa de um tenant acessar NF-e de outro:** 404/403, jamais vazar. (Task 8)
5. **XML de documento já recebido (mesma chave) chega de novo:** `updateOrCreate` por chave, sem duplicar itens nem XML. (Task 13)
